# Как подключить камеру к oko-cloud

Простая инструкция для обычного пользователя. Технических слов — минимум, всё по шагам.

---

## Как это работает

Вы ставите маленькую программу-помощник — **«мост» (bridge)** — на любой компьютер в той же сети, где стоят камеры. Мост сам находит камеры в вашей сети и показывает их в личном кабинете списком. Вам остаётся выбрать свою камеру и ввести её **логин и пароль** — всё.

Если камера «скрытная» и не показалась сама — её можно добавить вручную, указав прямой адрес видео (ссылку). Об этом ниже.

---

## Шаг за шагом (обычный путь)

1. **Установите мост.** Запустите docker-контейнер моста на компьютере, который подключён к тому же роутеру, что и камеры. На Linux добавьте параметр `--network host` — без него мост не увидит камеры (это самая частая причина «ничего не нашли»).
2. **Дождитесь статуса «Мост подключён ✓»** в личном кабинете. После этого поиск камер запустится сам.
3. **Подождите до минуты.** Камеры будут появляться в списке «Найденные камеры» по мере обнаружения.
4. **Нажмите «Подключить» на своей камере** и введите её **логин и пароль**. Если не знаете — попробуйте стандартные (см. шпаргалку ниже). Очень часто это **admin** и **пустой пароль**.
5. **Проверьте кадр-превью.** Если видите картинку с камеры — всё работает. Нажмите «Подключить в облако».

> Совет: после успешного подключения смените стандартный пароль камеры в её родном приложении. Пустой или заводской пароль небезопасен.

---

## Если камеру не нашли

Пройдитесь по пунктам сверху вниз — обычно решается за минуту.

1. **Камера включена и в сети?** Проверьте индикатор, кабель или Wi-Fi. Дайте камере 1–2 минуты после включения → нажмите «Искать снова».
2. **Камера и мост в одной сети?** Оба должны быть подключены к одному роутеру. Если камера на другом Wi-Fi, на гостевой сети или через мобильный интернет — мост её не увидит. Учтите: многие камеры работают только на **Wi-Fi 2.4 ГГц**, на 5 ГГц не находятся.
3. **Включён ли ONVIF в камере?** У многих камер эта функция **выключена с завода** и включается в родном приложении камеры одним тумблером. Где именно — смотрите шпаргалку по брендам ниже.
4. **Мост правильно запущен?** На **Linux** нужен `--network host` — иначе мост изолирован и камер не видит. На **Mac** авто-поиск камер, как правило, **не работает** из-за особенностей docker — добавляйте камеру вручную по ссылке.
5. **Всё равно нет?** Добавьте камеру вручную по прямой ссылке (RTSP) — это работает даже для камер без авто-обнаружения.

## Шпаргалка по брендам

Логин почти всегда `admin`. Пустой пароль в ссылке пишется так: `admin:@` (двоеточие есть, пароля нет). В RTSP-адресах замените `{IP}` на IP-адрес камеры.

> ⚠️ Точные пути и порты **зависят от модели и прошивки** — если один вариант не сработал, попробуйте соседний из той же строки.

### Китайские «универсальные» камеры (P2P-приложения)

| Бренд / приложение | ONVIF по умолчанию | Где включить | Логин / пароль | RTSP-ссылка (main) |
|---|---|---|---|---|
| **V380 / V380 Pro** | ВЫКЛ (тумблер) | Приложение V380 → камера → «⋮» / шестерёнка → Настройки → Дополнительно → **ONVIF** | `admin` / *(пусто)* или заданный в приложении | `rtsp://admin:@{IP}:554/live/ch00_0` (sub: `ch00_1`) |
| **iCSee / iCSee Pro** | ⚠️ зависит от модели, часто тумблера нет | Настройки устройства → сеть / дополнительно (если пункт есть) | `admin` / `admin` или `admin` / *(пусто)* | `rtsp://{IP}:554/user=admin&password=&channel=1&stream=0.sdp?real_stream` |
| **XMEye (Xiongmai)** | обычно ВКЛ | Веб-интерфейс камеры (не в мобилке) | `admin` / *(пусто)* или `admin` / `admin` | `rtsp://admin:@{IP}:554/user=admin&password=&channel=1&stream=0.sdp?real_stream` (короткий вариант: `/1` main, `/2` sub) |
| **Sricam / SriHome** | обычно ВКЛ | Настройки камеры в приложении | `admin` / `888888` или `admin` / *(пусто)* | `rtsp://admin:888888@{IP}:554/onvif1` (sub: `onvif2`) |

> Нюансы: у V380 порты могут снова закрыться после перезагрузки или сброса. У **iCSee** сообщество советует ONVIF **не включать** — у части прошивок это вызывает зависание камеры; при этом RTSP нередко работает и без него. У **Sricam** ONVIF-порт часто нестандартный (**5000**), поэтому авто-поиск может промахнуться — добавляйте вручную по RTSP.

### «Настоящие» ONVIF-камеры (подключаются легко)

| Бренд | ONVIF по умолчанию | Где включить | Логин / пароль | RTSP-ссылка (main) |
|---|---|---|---|---|
| **Hikvision** | часто ВЫКЛ | Веб камеры по IP → Network → Advanced → Integration Protocol → Enable ONVIF (+ создать ONVIF-пользователя) | `admin` / *задаётся при первой активации* (заводского пароля нет) | `rtsp://admin:пароль@{IP}:554/Streaming/Channels/101` (sub: `102`) |
| **Dahua** | обычно ВКЛ | Веб по IP → Network → Port → ONVIF (+ пользователь в Account) | `admin` / `admin` (старые) или заданный | `rtsp://admin:пароль@{IP}:554/cam/realmonitor?channel=1&subtype=0` (sub: `subtype=1`) |
| **Amcrest** (OEM Dahua) | ВКЛ | Работает из коробки | `admin` / заданный (старые `admin`/`admin`) | `rtsp://admin:пароль@{IP}:554/cam/realmonitor?channel=1&subtype=0` |
| **Uniview (UNV)** | ВКЛ | Работает из коробки | `admin` / `123456` (сменить при активации) | `rtsp://admin:123456@{IP}:554/media/video1` (sub: `video2`) |
| **Reolink** | ВЫКЛ | Веб камеры по IP → Network → Advanced → Port Settings → включить RTSP и ONVIF | `admin` / `admin` или *(пусто)*, либо заданный | `rtsp://admin:пароль@{IP}:554/h264Preview_01_main` (sub: `_sub`; H.265: `h265Preview_01_main`) |
| **TP-Link Tapo** | ВКЛ (нужен «аккаунт камеры») | Приложение Tapo → камера → Настройки → Дополнительно → **Camera Account** (создать логин+пароль) | логин/пароль из **Camera Account** (НЕ облачный аккаунт Tapo) | `rtsp://логин:пароль@{IP}:554/stream1` (sub: `stream2`) |
| **EZVIZ** | ВЫКЛ | Приложение EZVIZ → Профиль → Настройки → LAN Live View → камера → Enable RTSP | `admin` / **код проверки** (6 заглавных символов с наклейки на камере) | `rtsp://admin:КОДПРОВЕРКИ@{IP}:554/Streaming/Channels/101` (sub: `102`) |

> Три бренда с «сюрпризом» в паролях: **EZVIZ** — пароль это код проверки с наклейки; **Tapo** — нужен отдельный «аккаунт камеры»; **Hikvision/Dahua/Amcrest** — заводского пароля нет, вы задали его сами при первой настройке (забыли → сброс через утилиту SADP / кнопку).
>
> Важно про батарейные Wi-Fi камеры: **Reolink** (Argus, E1) и **Tapo** (C400/C420/C425, D230, дверные звонки) как отдельные устройства RTSP/ONVIF **не отдают вообще** — их к oko-cloud не подключить. Нужны проводные / PoE модели или подключение через фирменный NVR.

### Камеры из «умных» приложений (сложно или нельзя)

| Бренд / приложение | Реально подключить? | Что делать |
|---|---|---|
| **CamHi / CamHiPro** | ✅ Да | Под P2P-оболочкой это обычные ONVIF-камеры. Мост найдёт сам. Если нет — включить ONVIF в приложении (System / Дополнительно). Логин `admin` / `admin` или *(пусто)*. RTSP: `rtsp://admin:admin@{IP}:554/11` (sub: `/12`), ONVIF-порт обычно 8080 |
| **Tuya / Smart Life** | ⚠️ Обычно нет | Проверьте: настройки камеры → есть ли пункт **ONVIF / RTSP**. Есть → включите, задайте пароль. Нет → эту камеру обычным способом не подключить (см. раздел «Честно») |
| **Aqara** | ⚠️ Технически да, но морока | Только модели с RTSP (G3, G2H Pro, G4, G5 Pro). Включить RTSP в приложении Aqara Home, скопировать оттуда полную ссылку с токеном, добавить вручную. Обнаружения нет, токен рвётся при перезагрузке камеры |
| **YCC365 / YCC365 Plus** | ⚠️ Ненадёжно | Попробуйте вручную `rtsp://admin:@{IP}:554/live/ch00_0` (пароль пустой или `123456`). Может работать, но обновление прошивки часто ломает локальный доступ. Полагаться нельзя |
| **EseeCloud / IP Pro / VEEPAI** | ⚠️ Зависит от модели | Многие Wi-Fi камеры — только облако, RTSP нет физически. Где есть: `rtsp://admin:пароль@{IP}:554/11` (sub: `/12`), логин `admin`/`admin` |
| **Ring, Nest, Blink, Arlo, Wyze (сток), облачные EZVIZ** | ❌ Нет | Работают только со своим облаком. К oko-cloud не подключаются — нужна замена камеры на ONVIF-модель |

## Ручное добавление по ссылке (RTSP)

**RTSP** — это просто прямой адрес видеопотока камеры, вроде адреса сайта, только для видео. Если камера не нашлась сама, вы даёте oko-cloud этот адрес напрямую.

Как собрать ссылку:
1. Возьмите **IP-адрес** камеры (его можно посмотреть в приложении камеры или в настройках роутера — список подключённых устройств).
2. Возьмите **логин и пароль** камеры.
3. Возьмите **путь потока** для вашего бренда из шпаргалки выше.

Ссылка складывается по шаблону:

```
rtsp://ЛОГИН:ПАРОЛЬ@IP:554/путь
```

Пример для V380 с пустым паролем:

```
rtsp://admin:@192.168.1.50:554/live/ch00_0
```

В форме ручного добавления заполните IP, порт (обычно **554**), логин, пароль и выберите путь из списка. Нажмите **«Проверить»** — если появился кадр, сохраняйте.

> Если ссылка не сработала — попробуйте другой путь из той же строки шпаргалки: у разных прошилок одного бренда пути отличаются.

## Честно: какие камеры подключить не получится

Некоторые камеры сделаны так, что отдают видео **только своему облаку** и никак иначе. Их к oko-cloud (и к любому стороннему сервису) подключить нельзя:

- **Ring, Nest, Blink, Arlo, Wyze (стоковая прошивка), облачные EZVIZ** — принципиально закрыты. Только замена камеры.
- **Большинство Tuya / Smart Life** без тумблера ONVIF — обычному пользователю не подключить.
- **Aqara** — формально можно, но токен-ссылку надо копировать вручную, обнаружения нет, и поток рвётся при перезагрузке камеры. Годится только для терпеливых.
- **YCC365** и **многие облачные EseeCloud/Wi-Fi камеры** — либо RTSP нет вовсе, либо он отваливается после обновления прошивки. Полагаться нельзя.
- **Батарейные Wi-Fi камеры** (Reolink Argus/E1, Tapo C4xx/D230, дверные звонки) — у них нет RTSP/ONVIF физически.

**Простой само-тест перед покупкой или подключением:** зайдите в приложение камеры → Настройки → ищите слово **ONVIF** или **RTSP**.
- Есть тумблер → включите, введите логин/пароль в oko-cloud. Готово.
- Нет тумблера, и камера из списка Tuya / Ring / Nest / Blink / Arlo → эта камера работает только со своим приложением. Для oko-cloud нужна камера с поддержкой **ONVIF или RTSP** (подойдёт почти любая проводная камера Hikvision, Dahua, Reolink, Uniview, Amcrest, CamHi, а из бюджетных — V380/XMEye после включения ONVIF).
