# Стратегия распространения bridge + экосистема (research-заметка)

> Собрано research-workflow'ом по первоисточникам (HA/Frigate/Scrypted/MotionEye/Shinobi/ZoneMinder, коммерческие VSaaS, Linux-упаковка). Черновик для обсуждения, не финал.

# РЕКОМЕНДАЦИЯ для oko-cloud: распространение bridge + въезд в экосистему

## Рамка (главная мысль, которая всё упорядочивает)

Три исследования из четырёх сходятся в одном: это **не выбор «свой bridge ИЛИ чужие экосистемы»**, а **слои**, которые делаются в определённом порядке и переиспользуют друг друга:

1. **Ingest облака делается source-agnostic** (принимает RTSP/RTSPS от чего угодно) — это фундамент-keystone. Видео через код интеграций не гоняется; каждая интеграция после этого — тонкий адаптер, который просто регистрирует поток.
2. **Bridge остаётся ядровым продуктом** для основного рынка (украинский SMB — магазины, офисы, склады), которому нужен turnkey. Его НЕ депрецируем.
3. **Интеграции с HA/Scrypted/Frigate — это КАНАЛ привлечения** смежной prosumer-аудитории, а не замена bridge.

И два позиционных факта, которые надо зашить в маркетинг с самого начала, потому что они бесплатны и их не может предложить ни один local-first конкурент:
- **Украинский resilience-угол:** локальный NVR украли/уничтожили/выключили свет → записи пропали. Облачный оффсайт-бэкап решает ровно это. Честный, эмоционально сильный аргумент — и «крючок» для входа в анти-облачную экосистему («дополнение, а не замена»).
- **ONVIF-автообнаружение у вас УЖЕ есть** — это ровно тот UX, который в этой нише headline-фича (Camect «воткнул — само нашлось»), а у Frigate/MotionEye его НЕТ. Вынести на первый экран.

## 1. Как распространять bridge

### СЕЙЧАС (MVP — минимум обслуживания, максимум охвата)

**(1) Оставить multiarch Docker-образ в GHCR** — это валидированная база. Frigate доказывает, что docker-first жизнеспособен и даже доминирует в prosumer/HA-сегменте. Добавить только **cosign/Sigstore-подпись + публикацию digest** (GHCR умеет) — дёшево, сразу поднимает security-story.

**(2) Единый `install.sh` на брендовом коротком URL** (`get.oko.cloud`) по модели **Tailscale** — это лучшее ROI во всём распространении. Один скрипт: `uname -m` → arch (amd64/arm64/armv7), `/etc/os-release` → дистрибутив, ставит Docker если нет, `docker pull`, генерирует systemd-юнит `oko-bridge.service`, `enable --now`. Критично: **скрипт принимает `OKO_TOKEN` для zero-touch привязки**:

```
curl -fsSL https://get.oko.cloud | OKO_TOKEN=xxx sh
```

→ бридж поднялся, привязался к аккаунту, запустил ONVIF-дискавери. Токен — копипаст из ЛК. systemd = переживает ребут, `journalctl` для логов. Это прямой ответ на запрос владельца «поставить одной командой».

Ориентиры для копирования: `get.docker.com`, `tailscale.com/install.sh`, `ispyconnect` install-скрипт.

### ROADMAP (post-MVP, как пойдут B2B/парковые инсталляции и клиенты-админы)

**(3) Нативные подписанные APT/YUM-репозитории.** `.deb` для Debian/Ubuntu + `.rpm` для Fedora/RHEL, GPG-подпись пакетов и метаданных → `apt install oko-bridge` + автоматические `unattended-upgrades`. Золотой стандарт безопасности, «взрослый» дистрибутив, привычный любому линукс-админу. Два хода снижают стоимость:
- хостинг репо через **Cloudsmith/packagecloud/JFrog** (берут на себя подпись и метаданные);
- **★ важный рычаг для вашего стека:** паковать не Docker, а **bun-compiled standalone-бинарник** (`bun build --compile --target=bun-linux-arm64`/`-x64`/`-musl`). Тогда пакет чистый, без зависимости от Docker Engine (снимает боль «тяжёлый docker на слабом Pi»). Ориентиры: Ivideon (`packages.ivideon.com`), Grafana, Angelcam (`apt.angelcam.com`).

**(4) Готовый Pi-образ — только под железный трек.** Если появится «oko box» / turnkey для нетехнического сегмента — **CustomPiOS** (слой поверх Raspberry Pi OS Lite: бинарник + first-boot ввод токена/Wi-Fi), НЕ тяжёлый HAOS-путь через Buildroot. Ориентиры: OctoPi (CustomPiOS), Angelcam SD-образ, Camect. Для MVP избыточно.

### ПРОПУСТИТЬ

- **Snap** — strict-confinement душит ONVIF/multicast-дискавери (нужны пляски с `network-control`/`avahi-observe`), привязка к Canonical, Ubuntu-центрично. Показательно: Frigate snap не делает.
- **Flatpak** — десктоп-only, для серверного демона нерелевантно.

## 2. Экосистема: HA / Scrypted / Frigate

Порядок правильный: **сначала конфиг-совместимость (бесплатно), потом код-плагин под ваш стек, глубокую HA-интеграцию — последней и только под доказанный спрос.**

**go2rtc/Frigate — делать сразу, наивысший ROI.** Ключевой факт: **go2rtc встроен во все три** (HA несёт его в ядре с ~2024.11, Frigate использует внутри, Scrypted умеет rebroadcast). Значит совместимость с go2rtc = совместимость со всей экосистемой **через конфиг, без кода на каждую платформу**. Это не «плагин» (у Frigate нет plugin-стора) — это **документированные рецепты + шаблон go2rtc-конфига** и проверка, что ingest принимает то, что эмитит go2rtc. Дни–неделя. Цепляет Frigate/Blue Iris/NVR-аудиторию и косвенно HA+Scrypted.

**Scrypted-плагин — лучший effort/стек-fit, дешёвый полигон.** Плагины Scrypted пишутся на **TypeScript — ровно ваш стек** (единственная платформа с TS-нативным SDK). Публикация `@okocloud/scrypted-*` в npm = автоматически в Management Console магазине. Плагин «облачный sink» тонкий (Scrypted уже нормализует RTSP/ONVIF/rebroadcast). ~2–4 недели. Идеален как **низкорисковая TS-native валидация гипотезы «экосистема как канал»** до дорогой инвестиции в HA.

**Home Assistant — два разных входа, не путать:**
- **HA Add-on** (только HAOS/Supervised): **обёртка вокруг готового docker-образа oko-bridge** — `repository.json` в корне репо + `config.yaml` + `Dockerfile`. Пользователь вставляет URL GitHub-репо → add-on ставится в один клик. Технически ближе всего к тому, что уже есть; ваш ONVIF-автопоиск здесь killer-feature. ~1–2 недели (тонко).
- **HACS custom integration** — «родные» entity/управление из HA. Пишется на **Python (не TS!)** — это ограничение ядра HA, обойти нельзя. Самый большой пул нужной аудитории, НО: ~4–8 недель + **вечный maintenance-treadmill** (HA ломает API почти каждый релиз) + большой support-burden + Python выпадает из стека. **Строить ТОНКО (glue-only: config flow + регистрация RTSP-источников в облаке + сенсор статуса), видео мимо Python. Делать последней и только после подтверждения спроса.**

**Первый шаг, дающий больше всего пользователей при MVP-ресурсах:** открыть ingest (keystone) + рецепты go2rtc/Frigate. Это разом цепляет большой кусок экосистемы через конфиг, стоит меньше всего, и метрика «какие источники реально подключают» сама выберет HA vs Scrypted для следующей ставки.

**Риски экосистемы:**
- Аудитория HA/Frigate/Scrypted **анти-облачная по природе** — ставят локальный NVR именно чтобы не платить облаку. Продавать VSaaS «в лоб» = трение. Снимается позиционированием «оффсайт-бэкап + удалённый доступ ПОД вашей локальной системой», + украинский resilience-угол.
- HACS — maintenance-treadmill + требовательное вокальное комьюнити; плохая интеграция бьёт по репутации.
- Открытый ingest — **безопасность аутентификации чужих источников** + стоимость egress/трафика (у этой аудитории много камер — следить за cost-моделью).

## 4. Что скопировать напрямую

- **Tailscale** — `install.sh`, детектящий дистрибутив + zero-touch claim через authkey. Ваш эталон для задачи 2.
- **Camect** — auto-discovery как headline UX («воткни камеру — мост сам её нашёл»). У вас ONVIF WS-Discovery уже есть — вынести первым экраном.
- **Angelcam (Arrow, open-source)** — (а) много каналов дистрибуции под разный уровень пользователя, (б) **open-source клиента bridge** — критично для доверия к софту в сети камер клиента, особенно на укр. рынке, (в) элегантный пейринг **MAC+QR / UUID-ссылка без публичного IP и настройки firewall**.
- **Camcloud** — явное позиционирование **«no port-forwarding, encrypted tunnel»**. У вас rtsps уже есть — оформить как маркетинг.
- **Eagle Eye (appliance-паритет в софте)** — **локальный буфер при обрыве интернета** + edge-дедуп/motion для экономии трафика. То, чем софт-мост догоняет железо.
- **Frigate** — быть в **магазине интеграций Home Assistant** (add-on). Самый недооценённый канал.
- **Ivideon / Grafana** — официальный подписанный APT-репозиторий + install-скрипт (для roadmap-стадии).
- **Scrypted** — модель «плагин = npm-пакет, публикация = автоматом в магазине». Прямо ложится на ваш стек.

## Помечено — требует проверки перед реализацией

- **HA add-on / HACS манифесты** (`repository.json`, `config.yaml`, `hacs.json`) — сверять с developers.home-assistant.io и hacs.xyz напрямую; требования меняются.
- **HA-интеграции только на Python** — устойчивый факт, но подтвердить актуальный config-flow/discovery API.
- **Frigate camera setup wizard** — на момент исследования обсуждаемая фича (issue), не релизная; проверить в свежем релизе.
- **Scrypted SDK / публикация плагина** (`@scrypted/sdk`, `npx scrypted login`) — сверить текущий флоу.
- **bun `--compile` кросс-таргеты** (`bun-linux-arm64`, `-musl`, `-x64`) — проверить актуальные таргеты и что весь рантайм bridge компилируется без нативных зависимостей, несовместимых с single-file executable.
- **cosign/GHCR-подпись** — проверить актуальный флоу подписи и verify.
- **Безопасность открытого ingest** — аутентификация произвольных сторонних источников требует отдельного проектирования (это основная работа keystone-задачи, не «почти готово»).
- **Cost-модель egress/storage** для многокамерной prosumer-аудитории — заложить до открытия ingest.
- MotionEye ONVIF-автопоиск (в core отсутствует) и Linux-версия Camcloud Tunnel Manager — средняя/низкая уверенность источников; на решения не влияют, но не цитировать как факт.
